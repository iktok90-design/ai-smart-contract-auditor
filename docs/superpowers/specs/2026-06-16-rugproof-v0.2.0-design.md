# AuditSentry v0.2.0 — Design & Phased Build Plan

**Date:** 2026-06-16
**Branch:** `feature/v0.2.0`
**Author:** Omer Maksuti (with Claude Code)
**Status:** Awaiting approval

---

## 1. Context

AuditSentry shipped at **v0.1.0** as a deliberately complete *skeleton*: 38 commands, 19 agents, 33 skills, 9 MCP servers, 4 hooks, an on-chain soulbound audit-certificate contract, a GitHub Action, and a Pages site. Three independent deep-dives (commands+agents, MCP+scripts, skills+CI+docs+NFT) confirm the skeleton is **substantive and well-architected** — but it is a skeleton. The gap between "looks complete" and "is trustworthy" is what v0.2.0 closes.

### What's genuinely strong today
- Command and agent prompts are real, deep, and consistent (no thin stubs). `/audit`, `/audit-deep`, `/exploit`, `/invariant`, `exploit-poc-writer`, `invariant-writer`, `report-writer`, the protocol specialists.
- Skills are production-grade knowledge (reentrancy, AA, intents, cross-chain assessed at 9/10 depth).
- The NFT `AuditCertificate.sol` is real, soulbound-correct, and has passing tests.
- Helper scripts (`parse-slither`, `parse-mythril`, `sign-cert`, `render-*`, `notify-*`) are real implementations.
- CI has PR-audit, release, and Pages workflows that function.

### What's a skeleton / weak (the v0.2.0 target)
1. **MCP depth:** 3 of 9 servers (`block-explorer`, `tenderly`, and parts of others) return mock/stub data; several have fragility bugs (see §3 Phase 0).
2. **Zero automated tests** for the 9 MCP servers and 13 scripts. `test-mcp.ts` is a manual smoke runner, not a unit suite. This is the single biggest trust gap.
3. **CI gaps:** no linting, no SAST/secret scan, no e2e pipeline test, no version-sync check; `auditsentry-pr.yml` silently swallows forge build failures.
4. **Version drift:** `plugin.json` / `marketplace.json` say `0.1.0`; a `v0.1.1` commit exists but CHANGELOG has no 0.1.1 section.
5. **Detection breadth gaps:** no Vyper *agent* (only a skill), no L2/sequencer-risk specialist, no rug-pull/economic-modeling agent, no ZK-verifier coverage; missing skills (ve-lock governance, fee-on-transfer edge cases, signature malleability, MEV-PBS, liquidation cascades, oracle-redundancy failure, cross-contract state).
6. **Missing high-value commands:** dependency/version audit, multi-chain consistency, rug-check score, formal-verification (`/prover`), pre-deploy checklist.
7. **Docs incomplete:** no skill browser, no command cheatsheet/decision tree, no agent guide, no MCP reference, no config/troubleshooting/telemetry docs.
8. **Stale references:** `commands/exploit-live.md:87` marks `/bounty` as "TODO when available" though it exists.

### Decisions locked with the user
- **Scope:** all-of-it, phased toward **v0.2.0**.
- **Environment:** Foundry + Node installed; explorer API keys available; Slither/Mythril available — **but everything must stay offline-first** (graceful mock fallback, works with zero config).
- **Change latitude:** refactor existing files freely; don't break what works.
- **Release/git:** commit at the end of each phase on `feature/v0.2.0`; bump CHANGELOG per phase.

### Guiding principles
- **Offline-first is non-negotiable.** Every live integration (explorer, slither, mythril, token-safety API, tenderly) must detect absence of keys/tools and fall back to clearly-labeled mock data. A user with nothing installed must still get a working `/audit`.
- **Tests before depth.** Phase 1 builds the harness so Phase 2+ changes are verifiable.
- **Auto-generate docs from source** so they can't drift (skill browser, command cheatsheet generated from `skills/*/SKILL.md` and `commands/*.md`).
- **Each phase is independently shippable** and ends in a green build + a commit.

## 3. Phases

Each phase lists: **goal · concrete tasks (with file paths) · acceptance criteria · est. size**. Phases are ordered so each builds on a trustworthy base. "Est." is rough relative effort, not wall-clock.

### Phase 0 — Cleanup, bug-fixes, version reconcile (foundation)
**Goal:** Remove rot and fix the concrete bugs the deep-dives found, so later work sits on solid ground.

Tasks:
1. **Version reconcile:** bump `plugin.json`, `marketplace.json` to `0.2.0`; add a proper `[0.1.1]` historical section + `[0.2.0] Unreleased` to `CHANGELOG.md`. Cross-check `mcp/package.json`, `scripts/package.json`, `nft/foundry.toml`.
2. **Stale ref:** fix `commands/exploit-live.md:~87` (`/bounty` exists — remove "TODO when available").
3. **MCP bug fixes:**
   - `block-explorer-mcp/src/index.ts:~215` — `get_runtime_code` module routing.
   - `token-metadata-mcp/src/index.ts:~139` — implement real EIP-55 checksum (currently a comment).
   - `c4-history-mcp/src/index.ts:~77` & `sherlock-history-mcp/src/index.ts:~78` — robust protocol/contest name extraction (don't assume `YYYY-MM-*` / `-judging`).
   - `forge-runner-mcp/src/index.ts:~122` — when falling back to mock, set a `stub:true` flag and a visible warning in the response.
   - `hardhat-runner-mcp/src/index.ts` — shell-quote script/cwd paths (injection hardening).
   - `tenderly-mcp/src/index.ts:~93` — make simulation `gas` configurable (input param, default 5M).
   - `anvil-mcp/src/index.ts:~122` — replace fixed 1.5s sleep with RPC readiness polling (poll `eth_blockNumber` with timeout).
4. **Shared offline/stub convention:** define a single `{ stub: true, reason }` shape used by every server's fallback so the test suite and UI can detect mock data uniformly.

Acceptance: `make build` green; `node scripts/dist/test-mcp.js` 9/9; manual diff review; one commit `chore(v0.2.0): version reconcile + MCP bug fixes`.
**Est: S–M.**

### Phase 1 — Test & CI hardening (make it trustworthy)
**Goal:** Real automated tests for MCPs + scripts and a CI that actually gates quality. This is the keystone phase.

Tasks:
1. **Test runner:** add `vitest` to `mcp/` and `scripts/` dev deps; `mcp/test/` + `scripts/test/`.
2. **MCP unit tests:** per server, test each exposed tool's happy path, its offline/stub fallback, and input validation (Zod) rejection. Mock `child_process`/`fetch` where needed. Target every tool listed in `plugin.json`.
3. **Script unit tests:** `parse-slither` (severity remap + detector mapping + grading), `parse-mythril` (SWC mapping + grading), `sign-cert` (EIP-712 digest + recovery round-trip against a known key), `render-report`/`render-card` (template renders + graceful no-wkhtmltopdf path), `notify-slack`/`notify-discord` (block/embed shape, severity filtering — mock webhook).
4. **CI upgrades** (`.github/workflows/`):
   - New `lint` job: ESLint (mcp + scripts, with a security-rules preset), `forge fmt --check` (nft), `markdownlint` (commands/agents/skills/docs).
   - New `test` job: run vitest suites + `forge test` + `test-mcp.ts` as a hard gate.
   - New **e2e job**: run the audit → JSON → HTML → PNG pipeline on `examples/VulnerableVault.sol` and assert all artifacts exist + JSON validates against a schema.
   - **Version-sync check:** script asserting all manifests + CHANGELOG agree before a release tag.
   - **Secret scan:** gitleaks (or trufflehog) on PRs.
   - Fix `auditsentry-pr.yml` silent `forge build` failure → hard fail (or explicit `continue-on-error` with surfaced annotation).
5. **JSON schema:** publish `schemas/finding.schema.json` (the AuditSentry findings format) and validate report output + parser output against it.

Acceptance: CI green on PR; tests fail loudly when a parser mapping is broken (prove with a deliberate temporary break); commit `test(v0.2.0): MCP + script unit suites and CI gates`.
**Est: L.** (Highest-value phase.)

### Phase 2 — MCP depth & real integrations (offline-first)
**Goal:** Turn stubs into real, key-gated integrations that still work offline.

Tasks:
1. **Shared `mcp/_shared/`:** `rpc.ts` (retry + exponential backoff + 429 handling + rate-limit), `offline.ts` (`isOffline()`, `stub()` helper), `cache.ts` (hashed file cache w/ TTL).
2. **`block-explorer-mcp`:** real **Etherscan v2 multichain** API (single key, `chainid` param) for source, ABI, runtime code, proxy detection, verification status; mock fallback when no key; wire through `rpc.ts` for retry.
3. **`token-metadata-mcp` + safety:** add `check_safety` tool backed by a token-safety API (e.g. GoPlus/Blockaid) with offline fallback to the existing hardcoded quirks DB (honeypot, fee-on-transfer, blacklist, mint authority, proxy-upgradeable flags).
4. **`tenderly-mcp`:** make simulation params configurable; document the creds-gated path; ensure mock path is labeled.
5. **NEW `slither-runner-mcp`:** detect `slither` on PATH; if present run it and pipe through existing `parse-slither.ts`; else return labeled mock. Wire into `plugin.json` + `/slither`.
6. **NEW `mythril-runner-mcp`:** same pattern with `myth analyze -o json` + `parse-mythril.ts`. Wire into `/mythril`.
7. **Contract-analysis cache:** key forge/slither/mythril results by source hash so re-audits of unchanged files are instant (ties into the `caching-and-incremental` skill).

Acceptance: with keys/tools present, real data flows; with `RUGPROOF_OFFLINE=1` or nothing installed, every tool returns labeled stubs and tests pass in both modes; commit `feat(v0.2.0): real explorer/slither/mythril integrations w/ offline fallback`.
**Est: L.**

### Phase 3 — Detection breadth (agents, skills, commands)
**Goal:** Close the coverage gaps the audit surfaced.

New agents (`agents/`):
- `vyper-specialist.md` — Vyper compiler-class bugs (the 2023 Curve reentrancy class), decorator/visibility, `@nonreentrant`, immutables, default-function, no-delegatecall assumptions; pairs with the existing `vyper-specific` skill.
- `l2-sequencer-specialist.md` — sequencer downtime, force-include windows, L1↔L2 finality, `block.number`/`block.timestamp` semantics per rollup, Chainlink L2 sequencer-uptime feed usage, withdrawal delays.
- `economic-rug-specialist.md` — rug vectors (owner drain, infinite mint, pause-forever, blacklist, unilateral reward/fee changes), tokenomics death-spirals, LST depeg cascade modeling; emits a "rugability" sub-score.
- `zk-verifier-specialist.md` — verifier-contract correctness, trusted-setup assumptions, public-input binding, proof malleability, pairing-check misuse.

New skills (`skills/<name>/SKILL.md`, matching existing format: detection patterns, severity rubric, false-positive notes, remediation, real-world refs):
- `ve-lock-governance`, `fee-on-transfer`, `signature-malleability`, `mev-pbs`, `liquidation-cascade`, `oracle-redundancy`, `cross-contract-state`, `zk-verifier-bugs`.

New commands (`commands/`):
- `audit-deps.md` — enumerate imported libs (OZ/Solady/etc.), resolve versions, cross-ref known-vulnerable-version advisories; offline fallback to a bundled advisory snapshot.
- `audit-multi-chain.md` — given an address, fork on N chains and diff config drift (oracle/fee/timelock/owner differences).
- `rug-check.md` — fast owner-power scan → rugability score + grade.
- `prover.md` — formal verification entrypoint: Halmos (default, offline) + optional Certora; structured property templates (ERC-20 balance, AMM-K, access-control).
- `pre-deploy.md` — interactive launch checklist (multisig, timelock, pause, emergency withdrawal, monitoring) → compliance report.

Cross-cutting:
- **Formalize agent dispatch** in `commands/audit.md`: an explicit protocol-type → specialist mapping table (currently implicit).
- Add a richer **vulnerable Vyper example** under `examples-vyper/` and wire it into `/demo`.

Acceptance: new agents/skills follow the established structure and pass markdownlint; `/audit` dispatch table documented; commit `feat(v0.2.0): vyper/L2/rug/zk specialists, 8 new skills, 5 new commands`.
**Est: L.**

### Phase 4 — DX & docs (marketplace-ready polish)
**Goal:** A complete, browsable docs site and a submit-ready repo.

Tasks:
1. **`scripts/src/generate-skill-docs.ts`** — parse every `skills/*/SKILL.md` → `docs/skills/<name>.html` + a searchable index. Runs in build so docs never drift.
2. **`scripts/src/generate-command-docs.ts`** — parse `commands/*.md` frontmatter → `docs/docs/commands.html` cheatsheet + an `/audit` vs `/audit-deep` vs `/quick-scan` decision tree.
3. **Agent guide** `docs/docs/agents.html` — when to use attacker/defender, how specialists compose, the dispatch table from Phase 3.
4. **MCP reference** `docs/docs/mcp-reference.html` — per-server tools, inputs/outputs, key requirements, offline behavior.
5. **Configuration guide** `docs/docs/configuration.html` — full `.auditsentry.yml` schema with recipes (CI-blocking, monorepo caching, ignore vendor code).
6. **Troubleshooting/FAQ** + **telemetry** docs (what's sent, opt-in/out).
7. **README/CHANGELOG/roadmap** refresh: mark Phase 2/3 roadmap items done, update counts (agents 19→23, skills 33→41, commands 38→43, MCPs 9→11).
8. **Output polish:** `/gas` before/after benchmark numbers; ensure `/report` PNG/PDF paths documented.

Acceptance: Pages build deploys; every skill/command reachable from the site; commit `docs(v0.2.0): skill browser, cheatsheets, MCP/config/troubleshooting + v0.2.0 release notes`.
**Est: M–L.**

### Phase 5 — Advanced / stretch (optional, post-core)
**Goal:** Differentiators, only after Phases 0–4 land.
- `diff-reports.ts` + `/diff-audit` real old-vs-new severity-delta reports.
- Continuous-monitoring MCP (event-ABI anomaly flags).
- Bug-bounty submission API integration (`/bounty-submit`).
- Multi-agent "consensus mode" for `/audit-strict` (≥3 specialists must agree before surfacing).
- Collaborative review workflow in HTML reports (comments/sign-offs).

Acceptance: each as its own commit; only if time allows. **Est: variable.**

## 4. Cross-cutting concerns

- **Testing strategy:** vitest for TS (mcp + scripts); forge for Solidity; e2e shell test for the report pipeline. Every new MCP tool ships with a test. TDD where practical for parsers/sign-cert.
- **Error handling:** all live calls go through `rpc.ts` (retry/backoff); all fallbacks return the uniform `{stub:true,reason}` shape; no silent failures (CI fix for forge build).
- **Backwards compatibility:** existing command/agent/skill names and the findings JSON shape stay stable; the schema is published, not changed. New flags are additive.
- **Security of the plugin itself:** secret-scan + ESLint security rules + shell-quoting fixes; no secrets committed; API keys only via env.
- **Offline-first verification:** CI runs the suite with `RUGPROOF_OFFLINE=1` to prove the zero-config path.

## 5. Risks & mitigations

| Risk | Mitigation |
|------|-----------|
| Live APIs (Etherscan v2, GoPlus) change/shape-drift | Thin adapter + offline fallback + tests pin the adapter contract |
| Scope is large; sessions span days | Strict phase ordering; each phase independently shippable + committed |
| Slither/Mythril not on a given machine | Runner MCPs detect-and-mock; never hard-depend |
| Refactor breaks existing behavior | Phase 1 test harness lands first; e2e guards the pipeline |
| Docs drift from source | Generate skill/command docs from source in build |

## 6. Execution / checkpoints

- Order: **0 → 1 → 2 → 3 → 4 → (5 optional)**.
- Recommend doing **0 + 1 together first** (foundation + tests) since everything else relies on them.
- One commit per phase on `feature/v0.2.0`; brief check-in at each phase boundary; CHANGELOG updated each phase.
- Final: PR `feature/v0.2.0 → main`, tag `v0.2.0`, update marketplace metadata.

## 7. Out of scope for v0.2.0
- Public dynamic audit gallery backend (roadmap Phase 5).
- Mainnet deployment of the certificate contract (roadmap Phase 6).
- Non-EVM language depth beyond top vuln classes (Stylus/CosmWasm/Solana stay at current coverage).
